# 읽기 탐색과 정적 본문 렌더링 설계

## 목적

`namonak.dev`를 읽기 중심의 한국어 개발 블로그로 유지하면서, 정적 배포물의 글 본문 누락을 막고 홈에서 주제와 태그를 바로 탐색할 수 있게 한다.

대상 독자는 특정 기술 글을 읽거나 주제별로 과거 글을 찾아보려는 개발자다. 홈의 단일 역할은 최근 글을 빠르게 읽기 시작하게 하고, 필요하면 기존 카테고리·태그 경로로 이동하게 하는 것이다.

## 승인된 동작

### 정적 본문 검증

- 공개 글의 Markdown 본문은 개발 서버와 `npm run build` 결과 모두에 렌더링되어야 한다.
- 회귀 검증은 새 글 하나의 `dist/<category>/<slug>/index.html`에서 `.prose`의 의미 있는 본문 텍스트를 확인한다.
- 본문이 없는 글을 의도적으로 지원하지 않는다. 본문이 비면 검증이 실패해야 한다.
- Mermaid가 있는 글은 기존 build-time SVG 렌더링과 `validate:mermaid` 흐름을 유지한다.

### 탐색

- 데스크톱 홈의 `Categories` 목록은 각 `/categories/<category>/`로 이동하는 링크다.
- 글 카드의 태그 칩은 상세 글 태그와 같은 `/tags/<encoded-tag>/` 링크다.
- 홈에는 최신 12개 글만 표시한다. 더 오래된 글은 기존 카테고리 화면에서 탐색한다.
- 홈에는 카테고리 목록으로 가는 명확한 링크를 둔다. 새 아카이브, 검색, 페이지네이션은 만들지 않는다.

### 시각 언어

- 현재의 밝은 표면, 짙은 남색 본문, 파란 강조색과 넓은 여백을 유지한다.
- 메타데이터·카테고리·태그에 시스템 모노스페이스를 제한적으로 적용해 “작업 기록의 인덱스”라는 단서를 만든다.
- 카드와 주제 패널에는 얇은 규칙과 정렬을 사용하며, 장식용 아이콘·애니메이션·새 폰트 의존성은 추가하지 않는다.
- 키보드 포커스, 모바일 줄바꿈, 코드·표의 내부 가로 스크롤은 현재 동작을 보존한다.

## 변경 경계

| 영역 | 책임 |
| --- | --- |
| `src/content.config.ts` 또는 콘텐츠 로더 경로 | 새 Markdown의 정적 본문이 누락되는 원인을 해결한다. |
| `tests/` | 빌드 산출물 본문, 홈 글 수, 카테고리·태그 링크를 검증한다. |
| `src/lib/posts.ts` | 홈에 전달할 최신 글 수 제한을 명시한다. |
| `src/pages/index.astro` | 최근 글 12개, 작동하는 카테고리 탐색, 카테고리 목록 링크를 렌더링한다. |
| `src/components/PostCard.astro` | 태그를 태그 경로 링크로 렌더링한다. |
| `src/styles/global.css` 및 해당 컴포넌트 스타일 | 승인한 인덱스형 메타데이터 표현을 적용한다. |

발행 URL `/{category}/{slug}/`, 기존 카테고리·태그 경로, Markdown 콘텐츠의 문구는 변경하지 않는다.

## 오류 처리와 검증

- 콘텐츠 검증이 본문 누락을 발견하면 테스트가 실패해 배포 전에 멈춘다.
- `npm run check`, `npm run test`, `npm run build`를 실행한다.
- 홈·카테고리·태그·대표 글을 데스크톱, 태블릿, 모바일에서 점검한다.
- 정적 `dist` 파일에 대표 글의 본문이 포함됐는지 다시 확인한다.
