시스템 설계에서 데이터베이스는 데이터를 저장·검색·조직하는 핵심 구성 요소입니다. 이 글은 데이터베이스의 대표 유형, 스케일링 방식, 성능과 보안을 검토할 때의 기본 항목을 정리합니다.

## 데이터베이스 유형

| 유형 | 예시 | 주된 특징과 쓰임 |
| --- | --- | --- |
| 관계형 데이터베이스 | PostgreSQL, MySQL, SQLite | 테이블과 SQL을 기반으로 합니다. 트랜잭션, 관계 조회, 데이터 무결성이 중요한 작업에 적합합니다. |
| NoSQL 데이터베이스 | MongoDB, Cassandra, Redis | 문서·키-값·컬럼 패밀리 등 여러 모델을 포함합니다. 데이터 모델과 일관성 요구 사항에 맞춰 선택합니다. |
| 인메모리 데이터베이스 | Redis, Memcached | 메모리에서 빠르게 접근할 수 있어 캐시, 세션, 짧은 수명의 데이터에 주로 사용합니다. |

NoSQL은 하나의 제품군이 아닙니다. 고정 스키마를 강제하지 않는 문서형 데이터베이스도 있지만, 데이터 구조의 검증이나 제약이 전혀 필요 없다는 뜻은 아닙니다. 접근 패턴, 데이터 관계, 장애 시 요구하는 일관성을 기준으로 모델을 선택합니다.

## ACID 속성

관계형 데이터베이스의 트랜잭션을 설명할 때 자주 쓰는 ACID는 다음 네 속성의 약자입니다.

- **Atomicity(원자성)**: 트랜잭션의 작업이 모두 반영되거나 모두 취소됩니다.
- **Consistency(일관성)**: 트랜잭션 전후에 정의된 데이터 제약을 만족합니다.
- **Isolation(격리성)**: 동시에 실행되는 트랜잭션이 서로에게 미치는 영향을 제어합니다.
- **Durability(지속성)**: 커밋된 결과가 장애 뒤에도 보존됩니다.

실제 격리 수준과 내구성 보장은 데이터베이스와 설정에 따라 다릅니다. 따라서 결제, 재고, 예약처럼 오류 비용이 큰 작업은 제품 요구 사항을 먼저 정하고 해당 데이터베이스의 트랜잭션 동작을 확인해야 합니다.

## 데이터베이스 스케일링

### 수직 스케일링(Scale up)

단일 서버의 CPU, 메모리, 저장소 성능을 높이는 방식입니다. 운영 구조가 비교적 단순하지만, 장비 한계와 단일 장애 지점의 문제를 함께 검토해야 합니다.

### 수평 스케일링(Scale out)

여러 서버를 추가해 부하와 데이터를 나누는 방식입니다. 대표적으로 읽기 복제본과 샤딩을 사용합니다.

- **복제(Replication)**: 여러 노드에 데이터를 복제해 읽기 처리나 장애 대응을 돕습니다. 복제 지연과 읽기 일관성의 규칙을 정해야 합니다.
- **샤딩(Sharding)**: 키 범위나 해시 등으로 데이터를 여러 노드에 나눕니다. 분할 키, 재분배, 교차 샤드 조회의 비용을 설계해야 합니다.

스케일 아웃은 서버 수를 늘리는 것만으로 끝나지 않습니다. 데이터 분할, 장애 복구, 관찰성, 운영 절차가 함께 준비되어야 합니다.

## 성능 향상

- **캐싱**: 자주 읽는 데이터를 메모리에 보관해 원본 저장소의 부하와 응답 시간을 줄입니다. 만료와 무효화 규칙을 반드시 정합니다.
- **인덱싱**: 자주 사용하는 검색·정렬 조건에 인덱스를 둡니다. 인덱스는 읽기를 빠르게 할 수 있지만 쓰기 비용과 저장 공간도 늘립니다.
- **쿼리 점검**: 필요한 열만 조회하고, 실행 계획으로 병목을 확인합니다. `SELECT *`와 불필요한 조인·반복 쿼리는 실제 접근 패턴을 기준으로 검토합니다.

최적화는 추측보다 측정에서 시작합니다. 느린 쿼리 로그, 지연 시간, 처리량, 오류율을 보고 병목을 찾은 뒤 한 번에 하나의 가설을 검증하는 편이 안전합니다.

## 보안 우선순위

- 저장 중인 데이터와 전송 중인 데이터를 보호할 방법을 정합니다.
- SQL을 구성할 때는 문자열 결합 대신 준비된 문장 또는 바인딩을 사용해 SQL 인젝션 위험을 줄입니다.
- 역할 기반 접근 제어 등 최소 권한 원칙으로 데이터 접근 범위를 제한합니다.
- 백업도 운영 데이터와 같은 수준으로 접근 제어·암호화·복구 테스트의 대상에 포함합니다.

## CAP 이론에 대한 정정

원문은 CAP을 "일관성·가용성·분할 내성 중 두 가지만 달성"하는 선택으로 간단히 설명했습니다. 이는 널리 퍼진 축약이지만 정확한 표현은 아닙니다. 분할이 발생할 수 있는 분산 시스템에서 강한 일관성과 모든 요청의 가용성을 동시에 보장할 수 없다는 한계를 설명하는 정리입니다. 분할이 없는 모든 순간에 세 속성 중 하나를 포기한다는 뜻은 아닙니다. 자세한 논의는 Gilbert와 Brewer의 [*Perspectives on the CAP Theorem*](https://groups.csail.mit.edu/tds/papers/Gilbert/Brewer2.pdf)을 참고할 수 있습니다.

## 핵심 요약

- 관계형, NoSQL, 인메모리 데이터베이스는 각기 다른 데이터 모델과 접근 패턴에 맞습니다.
- ACID 요구 사항과 실제 트랜잭션 동작을 구분해 중요한 데이터의 일관성을 설계합니다.
- 수직·수평 스케일링은 데이터 분할, 복제 지연, 장애 복구까지 포함해 검토합니다.
- 캐시, 인덱스, 쿼리 최적화는 측정된 병목과 무효화·쓰기 비용을 함께 고려합니다.
- 보안과 백업·복구 검증은 데이터베이스 설계의 기본 조건입니다.
