## C 프로그램에서의 메모리

컴파일된 C 프로그램은 다음 세 종류의 메모리를 사용합니다.

### 정적(Static) / 전역(Global)

정적 또는 전역으로 선언된 변수는 정적·전역 메모리에 할당됩니다. 프로그램이 시작할 때 할당되어 프로그램이 종료될 때까지 메모리 공간에 남아 있습니다. 전역 변수의 접근 범위(scope)는 파일 전체이고, 정적 변수의 접근 범위는 해당 변수를 선언한 함수로 제한됩니다.

### 자동(Automatic) / 지역(Local)

지역 변수는 흔히 automatic으로도 부르며 함수 안에서 선언되고 함수가 호출될 때 생성됩니다. 접근 범위는 선언된 함수로 제한되고, 함수가 실행되는 동안에만 메모리에 존재합니다.

### 동적(Dynamic)

동적 메모리는 heap 메모리 영역에 할당되며 필요한 경우 해제됩니다. 포인터로 할당된 메모리 영역을 참조하고, 메모리를 해제하지 않는 한 계속 존재합니다.

## 접근 범위(scope)와 수명(Lifetime)

| 메모리 종류 | 접근 범위 | 수명 |
| --- | --- | --- |
| 전역 | 전체 파일 | 프로그램 실행 동안 유지 |
| 정적 | 선언된 함수 | 프로그램 실행 동안 유지 |
| 로컬(자동) | 선언된 함수 | 함수 실행 동안 유지 |
| 동적 | 참조하는 포인터 | 메모리 해제 전까지 유지 |

포인터 변수는 다른 변수, 객체(Object), 함수의 메모리상 주소를 포함합니다. 여기서 객체는 `malloc` 같은 메모리 할당 함수를 사용해 할당한 메모리를 말합니다.

포인터는 가리키는 대상에 따라 정수, 문자, 문자열, 구조체 등의 타입을 갖도록 선언됩니다. 그러나 포인터 자체는 가리키는 데이터 타입의 속성을 가지는 것이 아니라 주소를 담습니다.

## 포인터의 용도

- 빠르고 효율적인 코드 작성
- 다양한 문제에 대한 효과적인 해결 방법 제공
- 동적 메모리 할당 지원
- 작고 간결한 표현 사용
- 큰 오버헤드 없이 데이터 구조를 포인터로 전달
- 함수의 매개변수로 전달된 데이터 보호

## 포인터 사용 시 주의점

- 배열이나 데이터 구조의 경계를 넘는 접근
- 소멸한 자동·지역 변수 참조
- 해제된 heap 메모리 참조
- 아직 할당되지 않은 포인터 역참조

## 표준 문서에서의 포인터 동작 정의

[C99(ISO/IEC 9899:TC3)](http://www.open-std.org/jtc1/sc22/WG14/www/docs/n1256.pdf)는 구현 방법에 따라 정의된 행동, 명시되지 않은 행동, 정의되지 않은 행동을 구분합니다.

### 구현 방법에 따라 정의된 행동(Implementation-defined behavior)

구현은 동작을 문서화해 제공해야 합니다. 예를 들어 정수의 오른쪽 시프트 연산에서 상위 비트를 어떻게 확장하는지가 해당합니다.

### 명시되지 않은 행동(Unspecified behavior)

구현은 가능한 동작을 제공하지만 어떤 것을 택할지 문서화하지 않습니다. 예를 들어 `malloc`에 `0`을 인자로 주었을 때 실행마다 얼마나 할당되는지가 문제가 될 수 있습니다. 관련 목록은 CERT Secure Coding Appendix DD에서 확인할 수 있습니다.

### 정의되지 않은 행동(Undefined behavior)

포인터의 동작에 대해 어떤 결과도 강요하지 않으므로 여러 동작이 발생할 수 있습니다. 예를 들어 `free`로 해제된 포인터의 값이 해당합니다. 관련 목록은 CERT Secure Coding Appendix CC에서 확인할 수 있습니다.
