# 근거와 인용

## 출처 우선순위

표준, 공식 문서, 원 논문, 공식 API 문서를 우선합니다. 2차 출처는 배경과 맥락을 보완할 수 있지만, 핵심 기술 사실의 유일한 근거로 사용하지 않습니다.

수치, 인용, 지원 버전, 보안·성능 특성처럼 검증 가능한 주장은 출처와 연결합니다. 독립적으로 확인할 수 없는 사실은 쓰지 않거나, 불확실성과 적용 조건을 명시합니다.

## 주제 기반 글

주제를 가장 좁은 유효 범위로 정한 뒤, 핵심 주장 목록을 만듭니다. 각 주장에 1차 출처를 연결한 뒤에만 개요와 본문을 작성합니다.

## 아티클 기반 글

원문은 글의 출발점을 투명하게 밝히는 자료입니다. frontmatter 바로 다음에 다음 형식의 보이는 링크를 둡니다.

```md
> 원문: [원문 제목](원문 URL)
```

원문을 장문으로 인용하거나 단순 재서술하지 않습니다. 핵심 주장과 수치, 인용은 독립적으로 검증합니다.
원문과 검증 근거가 충돌하면 원문의 맥락이나 버전을 밝히고, 확인한 근거를 기준으로 바로잡습니다.

## GFM 각주

외부의 검증 가능한 기술 주장은 GFM 각주로 연결합니다. 식별자는 `[^source-id]`처럼 의미 있게 작성하며, 독자에게 보이는 번호와 본문 복귀 링크는 렌더러가 생성합니다.

```md
HTTP 상태 코드는 응답의 결과를 나타냅니다.[^rfc-9110]

[^rfc-9110]: [RFC 9110: HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110)
```

수동 `## 참고` 목록, 수동 번호, HTML 앵커는 사용하지 않습니다.

## 출처 충돌과 불확실성

출처 충돌을 숨기지 않습니다. 더 권위 있는 1차 출처를 기준으로 설명하고, 서로 다른 버전·환경·적용 조건이 충돌의 이유라면 그 차이를 글에 밝힙니다.
실무 경험은 검증 가능한 일반 사실이 아니라 경험으로 구분하고, 재현 조건과 한계를 함께 설명합니다.
