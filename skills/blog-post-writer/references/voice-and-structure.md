# 문체와 글 구성

## 독자와 어조

독자는 개발자입니다. 본문은 자연스러운 한국어 존댓말로 쓰며, 어려운 개념도 정확성을 잃지 않고 이해할 수 있게 설명합니다.

## 기본 전개

글은 주제에 맞게 `정의 → 원리 → 코드·예시 → 적용 또는 주의점 → 정리` 순서로 전개합니다.
모든 단계가 필요한 것은 아닙니다. 비교가 핵심이면 표를, 단계가 세 개 이상 이어지는 흐름이나 관계가 핵심이면 Mermaid를 선택적으로 사용합니다.

도입부는 2~4문장으로 개념과 독자가 글을 통해 얻을 결과를 제시합니다. 필요할 때만 “이 글에서는 … 살펴보겠습니다.”처럼 자연스럽게 안내합니다.

## 정확한 단정

검증된 사실은 “이때 … 합니다”, “이 메서드는 … 을 반환합니다”처럼 명료하게 설명합니다.
버전, 환경, 설정, 입력값에 따라 달라지는 내용은 적용 조건을 먼저 밝히고 절대적으로 단정하지 않습니다.

## 비유의 사용

어려운 핵심 개념에는 정확한 정의와 원리를 먼저 설명한 뒤, 이해를 돕는 짧은 비유를 덧붙일 수 있습니다.
비유는 서론 장식이나 정확한 기술 설명의 대체물이 아니며, 글의 기본 구조를 바꾸지 않습니다.

## 코드·표·Mermaid

- 코드 블록에는 `ts`, `js`, `kotlin`, `bash`처럼 언어 식별자를 붙입니다.
- 코드 설명, 지원 버전, 실행 결과가 일치하는지 확인합니다. 실행하지 못한 결과를 사실처럼 쓰지 않습니다.
- 넓은 코드와 표는 모바일에서도 읽을 수 있게 열 수와 열의 내용을 절제합니다.
- Mermaid는 `mermaid` fenced block으로 작성하고, 라벨을 간결하게 유지합니다.
